# Transplant the authorized runnable product closure

## Objective

Create the T1 local non-candidate checkpoint by moving the complete tracked runtime dependency
closure from the immutable U1 Git object into stable OmniMind responsibilities. Preserve the
authorized 4,014-file icon corpus byte-for-byte under source-neutral `line` and `fill` paths, replace
the product identity and first-party brand, remove the buildable `vendor/ui` mirror, and preserve
exact provenance through Git and the single root adoption record.

This Work owns the identity and distributable-asset seam that was previously described as a later
Work. The merge is deliberate: no adapted source tree may be born with temporary product identity,
old protocol/storage/package names, or an icon API that exposes its library source.

## Human calibration incorporated

The maintainer has supplied the controlling rights and visual facts for this Work:

- the fixed code and authorized icon corpus may be retained, adapted and redistributed in source
  and product artifacts;
- all 4,014 SVG files remain complete and byte-identical; no used-only pruning or replacement icon
  library is authorized;
- the former `reversed` family becomes `line`, while `fill` remains `fill`; individual semantic
  filenames do not change;
- the UI mother's compact geometry, density, interaction rhythm and light/dark behavior remain the
  visual envelope; path/API/identity takeover is not permission to redraw it;
- the first newly drawn Agent-slot/rail mark and its vermilion/orange-red treatment were rejected
  after real-surface review. This Work therefore wires the existing OmniMind Agent Dock light/dark
  icons as explicit temporary identity assets and does not guess another palette;
- Provider, Model and Engine rows always have a truthful icon. Reliable official marks and colors
  remain truthful integration facts; glyph-only sources use `currentColor`; unknown identities use
  a neutral first-party fallback and never borrow another brand;
- the default first-party user identity is OmniMind Agent; bundled Pi remains the disclosed native
  runtime and keeps Session, Package and execution authority;
- donor product identity is allowed only in the root README source/adoption disclosure. Real
  Provider, Engine, Model, service and legal identities are not donor contamination.
- the canonical V1 public origin is `https://omnimind.wisdomeyes.cn`, but it is reserved and
  inactive as of 2026-08-04. No website, docs, changelog, feedback API, download service or update
  service may be presented as online before its own activation proof exists;
- home, docs, changelog, download, privacy, support, feedback, reasonable share/social entry and
  release/update bridges remain OmniMind product responsibilities. Their fixed-source UI and
  capability lineage must survive even though donor domains, accounts, content, assets, backend
  implementations and marketing identity do not;
- a human-facing public origin, feedback submission endpoint and release/update authority are
  separate configuration and trust boundaries. None may be inferred from another, and none owns
  Conversation, Run, Queue, Session, Package private state, credentials or user files;
- inactive public capability must fail closed as unavailable, disabled or feature-gated. It may not
  become a broken link, guessed endpoint, fake page, fake payload, fake success or background retry.

This is the completed icon/runtime identity calibration and the current temporary brand decision.
It removes the prior replacement gate; final brand form and palette remain owned by the later
Agent/Chat Work and post-change same-state review may still reject material drift.

## Requirement traceability

This Work owns R1 and R2, all of R3 for the first runnable product closure, the source-transition
portion of R4 and the physical-lineage portion of R11. It also owns the product/package/storage/
protocol identity, first-party brand assets, icon corpus, Provider/Engine icon completeness and
artifact resource wiring required for the adapted tree to exist under one final product identity.

It carries A-01 by declaring exact expected-red execution debt before scans, A-03 by preserving the
approved mother and requiring post-change same-state proof, and A-04 by keeping T0 evidence tied to
its historical source SHA.

## In scope

  output, and classify every path as moved runtime source, required root closure, generated source,
  regenerated output, excluded non-product material, retained public-surface lineage, authorized
  icon corpus or replaced product identity asset.
- Move the whole runnable Web, Desktop, Server-to-Service and required contracts/shared closure.
  Update every workspace, import, static-client, child-spawn, smoke, package and artifact-resolution
  path needed for root install/build/typecheck and macOS launch.
- Move only root lock/config/patch/build/package scripts proven by the dependency trace. Exclude
  plans, audits, donor marketing implementation/content/assets, screenshots, contributor
  automation, archives, ignored dependencies, caches and generated build output. Preserve an exact
  disposition for the fixed public-surface paths and keep their current Product re-entry anchors.
- Establish the root ignore boundary required by the moved workspace so installed dependencies,
  workspace symlinks, caches, local profiles and generated build/test/package output cannot enter
  source, identity or clean-snapshot scans.
- Move all 1,979 line and 2,035 fill SVGs to `apps/web/public/icons/{line,fill}`. Preserve each
  individual semantic filename and byte digest. Build a path-independent integrity index covering
  all 4,014 files; the index validates resolution and packaging and may not prune unused files.
- Rename the permanent icon API to stable domain language such as `Glyph`, `GlyphStyle` and
  `registry`; remove the library-source name from production paths, symbols, tests and build
  metadata. Preserve mask/currentColor, slot, title/label, a11y and line/fill routing behavior.
- Make Provider, Model and Engine icon selection explicit across current real consumers. Preserve
  reliable official marks and verified official colors, use real glyph plus `currentColor` when the
  color is not reliable, inherit the Provider icon for a Model without its own mark, and use an
  OmniMind-owned neutral fallback for unknown identities. Pure-text and lookalike fallbacks fail.
- Replace all first-party product/package/environment/protocol/storage/update/bundle identifiers
  with stable OmniMind identity. Remove old aliases and dual registrations; there are no users or
  published compatibility obligations.
- Place the previously authored OmniMind Agent Dock light/dark icons under `assets/brand` as a
  temporary source and wire favicon, application, Dock/Taskbar, splash and required product exports
  to it. Preserve its bytes and prove coherent light/dark plus 16/20/24/32px behavior. Its existing
  color and gradient treatment is an explicit temporary exception, not the final palette.
- Make OmniMind Agent the default first-party visible identity without renaming or relocating Pi
  execution authority. Daily shell/Composer/empty-state/navigation surfaces do not repeatedly brand
  the runtime; About, Licenses, runtime detail and diagnostics keep exact Pi provenance discoverable.
- Remove prior product logo, favicon, app/Dock icon, splash, screenshots, donor share handles/cards,
  donor marketing graphics and donor product copy after their build inputs and visible consumers
  use the new identity. Do not remove real integration brands, mandatory legal names or the owned
  public-surface capability lineage merely because its network service is not active.
- Create `architecture/public-surface.md` as the sole owner for the canonical public origin,
  Public Surface Registry, activation gates, inactive behavior, app-to-public data direction,
  feedback security/privacy boundary and distribution/update authority separation. Register it in
  the root authority map, architecture index, Agent routing and execution brief without copying its
  registry into parallel documents.
- Replace guessed public exits in the current Web shell with one focused public-surface resolver.
  Docs and Changelog remain visible but unavailable when no production-approved public-site config
  exists. Public-site origin, feedback endpoint and update authority remain separate; do not add a
  generic endpoint manager or service registry.
- Remove the guessed feedback default. Without an explicitly approved production endpoint,
  submitting feedback performs no fetch and presents truthful unavailability. Preserve the draft
  on failure; do not synthesize success, silently retry, attach prompt/code/files/paths/credentials/
  environment/terminal content, or crash renderer, Conversation or Composer.
- Extend the existing document and identity gates rather than creating another whole-repository
  validator. The negative scan rejects `tryomnimind.com`, `trysynara.com` and `@trySynara` in
  production surfaces while preserving truthful fixed-source provenance and legal disclosure.
- Make the entire tracked tree and generated/artifact closure README-only for donor product
  identity. The identity checker reads its machine-readable denylist from the root README rather
  than duplicating the token in source. Tool/Bundle/research prose uses `U1`, `UI mother`, `fixed
  source`, `authorized icon corpus` or `donor identity`.
- Preserve mandatory attribution in the root README and exact legal text while keeping private
  authorization material out of the repository. The adoption rights field truthfully states
  authorized use/adaptation/redistribution without publishing personal relationships or private
  proof.
- Regenerate route source from authored routes. Establish a deterministic source for any claimed
  generated theme file, or remove its false generated status and treat it as reviewed source.
- Generate artifact-derived notice/SBOM inputs for the actual dependency and asset closure. Remove
  undeclared startup font/network dependencies or declare and prove their real privacy behavior.
- Use an isolated disposable development profile. It may launch the mechanically moved mixed
  backend only with synthetic local state and without real user data, workspace, credentials,
  global Pi state or a release artifact.
- Evolve the existing root `source-adoptions` record in the same move so it distinguishes immutable
  T0 revision/tree evidence from current adapted roots, original prefixes, material change classes,
  authorized assets and rights disposition. Do not create another source manifest.
- Update the source/identity checker only as needed to distinguish historical exact Git evidence
  from current adapted author paths and to enforce README-only donor identity across authored,
  generated and packaged output.
- Remove `vendor/ui` from the working tree after target closure and provenance proof exist. Git
  objects and the root disclosure remain the rollback/evidence path.
- Pre-enumerate the only expected-red execution debt: mechanically moved Product Service Pi
  executable dependencies and donor code-identity findings needed until later Product/Host Works.
  Product identity, old brand/API/path names and icon integrity are hard-green and may not enter that

## Out of scope

  Native Host.
- Final OmniMind brand redesign or palette selection; the rejected bar-chart-like mark and rejected
  vermilion/orange-red treatment must not ship from this Work, and no replacement color is guessed.
- Changing Pi native Session, Package or execution authority; placing Pi runtime code in Electron
  Main or renderer; or creating a second Agent Runtime.
- Rebuilding the UI mother as a new visual system, changing its approved geometry, or spreading the
  temporary icon colors into product accent, success, warning, error or diff tokens.
- Implementing complete custom Profiles, Package marketplace, Remote, external Engine framework,
  Windows/Linux packaging or the clean-public-repository cutover.
- Re-running unchanged T0 build/smoke without a trigger, importing prior product data, publishing
  private authorization evidence, or claiming production/Campaign completion.
- Building or deploying the public website, changing DNS/TLS, implementing a feedback backend,
  publishing downloads/updates, inventing telemetry or declaring any public surface online.

  `vendor/ui`; the worktree contains no buildable donor mirror.
- Frozen install, root build, typecheck, static-client serving, packaged-path focused checks and
  macOS desktop launch all use the moved target paths.
- The line corpus contains 1,979 files, fill contains 2,035 and total is 4,014. Relative semantic
  filenames and per-file bytes match the fixed source exactly; missing, extra, changed or individually
  renamed files are zero in source and tested artifact.
- Old icon paths and source-branded icon API symbols are zero. The stable resolver serves line/fill
  correctly in light/dark and packaged/static paths without a second functional icon system.
- Current Provider/Engine surfaces contain truthful icons; Model inheritance and neutral unknown
  fallback work; pure-text fallback and lookalike-brand substitution are zero.
- The temporary OmniMind Agent Dock light/dark source drives app icon, favicon, splash, About and
  default Agent identity coherently at micro sizes. The rejected replacement mark and its rejected
  vermilion/orange-red output are zero.
- Temporary icon colors do not become interaction/status/diff tokens and do not disturb the mother's
  neutral surfaces, density, geometry, focus or selection behavior.
- Donor logo/screenshots/share/marketing assets and product copy are absent from authored and tested
  artifacts. Public-surface capability lineage remains explicitly classified and re-enterable;
  mandatory legal text and real Provider/Engine/service identities remain truthful.
- Every fixed-source public-surface path has an exact `public-surface-lineage` disposition rather
  than being washed into generic non-product exclusion. The disposition count and full sorted
  record digest fail closed under missing, extra or reclassified records.
- The sole Public Surface owner records `https://omnimind.wisdomeyes.cn` as canonical but inactive,
  contains a complete registry for home, docs, changelog, download, privacy, support, feedback,
  share/social, update discovery and future deep link, and separates product entry, direction,
  data, activation, unavailable behavior and authority for each.
- Authored and built product surfaces contain no `tryomnimind.com`, `trysynara.com` or `@trySynara`.
  Docs and Changelog have no external action without approved production public-site config;
  Feedback has no network request without a separately approved production endpoint.

- Case-insensitive donor product identity is zero in paths, authored source/docs/tests/comments,

- Generated route/theme handling is deterministic and notice/SBOM inputs describe the actual

- T1 scans report two truthful sets: source/rights/icon/product-identity/root-to-vendor are hard

- The disposable profile contains no real workspace, credential or user state, produces no release

- The handoff records T0 identity, current commit, path disposition, icon digest proof, brand review,

## Falsifiers and stop conditions

- Stop if any authorized SVG changes bytes or semantic filename, if source/artifact cannot contain
  the complete 4,014 files, or if a second long-lived functional icon library is required.
- Stop if reliable Provider/Engine identity cannot be represented without a guessed official color,
  borrowed mark or plain-text fallback; use verified currentColor or the neutral fallback instead.
- Stop if the temporary prior icon cannot be wired coherently at micro size or on light/dark OS and
  product surfaces, or if the rejected replacement mark/color remains in output. Do not redesign a
  second speculative mark inside this Work.
- Stop if T0 Git evidence cannot be resolved, the root adoption record cannot express historical
  exactness plus current adapted roots, any target remains dependent on `vendor/ui`, or README-only
  identity cannot be enforced without erasing legal/integration truth.
- Stop if removing donor marketing implementation also erases the public capability lineage, if an
  inactive surface requires a guessed URL or fake success, or if public origin, feedback delivery
  and update authority can only be represented as one generic endpoint concept.
- Stop if the mixed backend needs real credentials/user data/global state, or if expected-red
  execution debt cannot remain exact and bounded. Do not broaden it after scan output.
