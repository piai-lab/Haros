# Recover Product B1 through exact alternate authority

## Decision

The maintainer permanently terminates product-truth complexity v9. It remains immutable failed
history and optional observational evidence only. It is not repaired, renamed, replaced by a new
meter version, or consumed as a Product B1 predecessor or acceptance gate.

Direct first-public B1 starts under this single alternate authority:

1. Main records the full base and candidate Git SHAs and reads the real
   `git diff --name-status -z --no-renames <base> <candidate>` result. Candidate configuration,
   reports, handoffs and meter artifacts cannot define, filter or authenticate that result.
2. The only authorized Git paths are the exact `direct-first-public-b1` production, measurement and
   dependency rows in its unchanged `omp-flow-production-boundary-v1` block plus the exact 16
   `direct-first-public-b1` rows in Design's
   [verification-path authority](../design.md#exact-per-work-verification-path-authority). Each path
   retains its authored presence, mode, lifecycle and purpose. Every other changed path fails the
   scope check. Runtime-generated temporary homes and isolated profiles are not Git paths.
3. Product behavior is accepted only by the frozen B1 evidence triad: the 10-owner/146-operation/
   87-state/85-race/65-kill capability verifier; real generated-home presence, fault, race and
   abrupt-kill tests; and a reviewer-owned complete raw-reference enumeration plus different-actor
   same-SHA source Review. Missing cases, unexplained references, incomplete enumeration or an
   escaping mutation is a B1 failure.
4. V1-v9 artifacts remain byte-preserved history. None can substitute for the real Git scope check,
   runtime evidence or source Review. No complexity meter is run as a B1 gate.

The Product scope and safety contract do not change: direct first-public creation, exact
destructive allowlist, Product/Service/Web refusal cuts, canonical Product database path,
Package-root sole authority preparation, compatibility deletion and later responsibility splits
remain as authored. Existing SQLite, LevelDB, lock and atomic-file mechanisms are reused. This
Decision authorizes no migration, backup, restore, second state track, semantic grammar, new
governance framework or production path.

Implementation is product-first within the single B1 Work: (A) correct live Product composition to
`<lane>/stores/product.sqlite`; (B) close Product/Service pre-mutation and lock-held refusal cuts and
the Web presence-only cut; (C) close destructive target/ancestor/content seals, strict decoders,
atomic delete-only batch and stale-lock/tombstone convergence; (D) delete compatibility residue and
prepare Package-root sole authority; then (E) use a thin checked-in generator/adapter and direct
per-owner tests to cover the already-existing capabilities. The frozen 10/146/87/85/65 catalog is
a coverage list, not permission to create a general event VM, second test runtime or governance
product. Old failed candidates may be read as local counterexamples only and are never cherry-picked
as a whole.

Scope authority never weakens destructive safety. Production and tests must not read, inspect,
copy, rename or delete the maintainer's real `~/.omnimind`; apply and destructive journeys run only
against immediately enumerated tool-created homes and isolated profiles. Unknown paths, symlinks or
reparse points, locked files, failed deletion, credentials, current Package generation, Pi-private
state, attachments and user workspaces remain fail-closed.

## Entry and completion

B1 may start immediately from this Decision and its exact Work boundaries. Its producer records one
immutable candidate SHA and writes the existing B1 handoff. One fresh different actor then reviews
that same SHA. Only a real destructive, data-loss or public-authority finding returns to a bounded
Product repair; workflow receipts, Review filenames and failed meter history cannot stop Product
work.
