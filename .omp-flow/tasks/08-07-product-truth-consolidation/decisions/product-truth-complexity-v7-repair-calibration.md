# Product-truth complexity v7 Occam repair calibration

## Human calibration applied

Main accepts the independent [v6 implementation Review](../reviews/product-truth-complexity-v6.md)
as `FAIL` under the maintainer's standing instruction to continue the fastest high-quality repair.
V5 and v6 remain immutable rejected evidence. Their repeated failure shows that a meter-owned
interpreter for arbitrary JavaScript/Effect aliasing, scheduling, loops, exceptions and resource
lifetime is an unbounded assurance liability, not the shortest safe route to the Product goal.

The selected v7 repair narrows the measurement authority to candidate-independent facts it can
mechanically prove: accepted Work/path membership, dependency and lock authority, resolved import
closure and direction, forbidden escape/import forms, exact raw-effect owner boundaries, complexity
and stable semantic counts. V7 must not claim static proof of runtime cleanup, refusal ordering,
lock-token reachability, scheduler behavior or catch/finally disposition, and must not contain a
general CFG/points-to/Promise/Effect interpreter or semantic source-overlay oracle.

Those behavioral obligations move to the B1 Work without weakening them. B1 must close raw effects
behind small owner-local runtime capabilities that do not expose scratch paths, generic database
handles or release primitives; use verifier-owned injected ports and event traces; exhaustively run
generated-home success/fault/presence/race/kill matrices; and undergo different-actor hidden
mutation plus source Review at one immutable SHA. The static v7 gate must prove there is no second
raw fs/SQLite/LevelDB/process path that can bypass those traced owners.

This decision authorizes only v7 PRD/Design/interface/Work-map repair followed by fresh
different-actor QbD. It does not authorize meter implementation before a zero-blocker/zero-advisory
QbD, B1 production work, destructive execution, dependency changes, Campaign promotion or any read
or mutation of real `~/.omnimind`.
