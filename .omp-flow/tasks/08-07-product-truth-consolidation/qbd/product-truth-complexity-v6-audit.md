## One candidate-fact authority

The closed semantic roots are sufficient without becoming self-proof. They name exact owner and
classifier declarations, exact lock acquire/release declarations and resolved filesystem, crypto,
SQLite, Promise/scheduler and Effect primitives. They do not assert freshness, provenance,
reachability, validation, held state, cleanup or terminal disposition. Those facts must be derived
from compiler/dependency symbols, call/return/throw edges, points-to flow and actual predecessor
states. Candidate/config text cannot provide a fact merely by repeating an authority token.

One Proof IR is a hard architectural condition, not an output reconciliation rule. Classifier,
owner-lock and legacy-refusal proof consume the same call contexts, value locations, loop edges,
completion records, event identities, pending tasks and resource dispositions. A later
category-specific scanner, source-position fallback, regular expression or helper-name recognizer
cannot satisfy the interface even if it reproduces a digest. Unsupported recursion, dispatch,
property access, scheduling, finalization, resource escape or bound overflow fails the affected
gate with a bounded witness; it never widens to a success fact.

The implementation remains finite. Call-string, points-to, abstract-state, event, task and loop
bounds are explicit report data. Exact constant pruning handles the required zero/one-iteration
controls; all other proof-relevant repetition reaches a bounded fixed point or fails closed. This
permits a complete implementation without pretending to interpret arbitrary JavaScript.

## Classifier provenance and all-completion closure

The resource model closes all four v5 classifier bypasses:

- Module activation and classifier invocation are different identities. A scratch token is valid
  only when every producing path allocates an exclusive current-invocation root; cache, caller,
  environment, module state, escape and loop-carried reuse are invalid.
- `RetiredBundle`, `ScratchRoot`, `CopyPath`, file handle, observed bytes/manifest and database
  handle are distinct typed tokens. A source/copy phi or current/raw/unbound path has a non-singleton
  or invalid origin and cannot become the approved copy merely by entering the named local.
- Source-before/source-after identity, destination identity/link facts, byte count, SHA-256 and
  repeated manifest are conjunctive events over the same tokens. Their success facts must dominate
  both copy-helper return and SQLite open; unreachable or post-return checks contribute no fact.
- After scratch acquisition, the shared completion graph follows normal, return, throw, catch and
  finally paths. After database open, close precedes exact-root remove and absence. A cleanup
  primitive may terminate fail-closed, but catch/return/finally cannot convert that failure into a
  valid completion or continue later work. Conditional, detached and wrong-resource cleanup do not
  meet the sequence.

This remains the one narrow retired-SQLite private-copy origin. It cannot authorize a current
Product/service store, source-in-place open, arbitrary temporary directory, general direct-tool
capability or retained evidence. Whole-union persistence discovery over `production` and
`direct-tool` members remains a separate conjunctive prerequisite.

## Loop epochs, predecessor meets and task joins

Each successful acquisition is a dynamic event token, not a callsite label. Entry/back/exit edges
and the bounded SCC fixed point make a second reachable loop traversal a new epoch. The meet at a
guard or sink retains `held` only if every actual predecessor carries the identical singleton token
and canonical binding. Branch-local acquisitions, reacquisition, release, escape, `many` and
unknown therefore cannot collapse to held at a later textual position. Exact `do...while(false)`
has one traversal; exact `while(false)` and the exact empty supported iterable have zero.

Scheduling is intentionally a may-harm dimension inside the must-hold proof. Any actual predecessor
with an unjoined release-capable task poisons the later sink; a branch with no task cannot intersect
that risk away. Locals, literal properties, parameters, returns and closure capture carry the lock
alias into the task. Only joining the same resolved task/Promise chain discharges that pending task;
joining an unrelated Promise does not. If the joined task released the lock, the resource state is
still `released`. A schedule in a repeatable loop is a new event/chain instance on the next
traversal and cannot be discharged by joining only one collapsed static callsite token.

Native Promise semantics must come from resolved library/protocol identity. Unknown thenables,
unresolved schedulers, timers/events without exact joins and Effect forks fail closed. The sole
Effect positive is the resolved acquireRelease→use→all-completion release bracket already selected
by authority; v6 does not infer an arbitrary combinator's scope from its name. These rules reject
both direct and captured-property v5 Promise witnesses while retaining no-schedule and exact joined
non-releasing controls.

## Legacy terminal disposition

V6 separates two necessary claims that v5 had partially conflated:

1. for every one of the `2^N` presence assignments, no assignment containing a present legacy
   identity may reach any current-generation sink; and
2. every reachable terminal for such an assignment must still carry the exact typed-reset throw
   after call, catch and finally processing.

Presence polarity is semantic (`exists=true` and Web non-null mean present), so reversed null and
negated-existence guards cannot pass by matching comparison tokens. Real zero-iteration edges expose
guards placed only inside an empty loop. Completion propagation exposes a reset swallowed by a
catch, conditionally rethrown under constant false, replaced by normal return, replaced by another
throw or overridden by `finally`. A normal `finally` resumes the pending reset; an abrupt finally
replaces it. Sink nonreachability cannot hide the replacement.

second measurement universe.
