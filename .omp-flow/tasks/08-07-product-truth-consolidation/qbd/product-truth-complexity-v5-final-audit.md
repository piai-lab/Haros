## Closure of the prior blocker

### Exact source and declaration authority

The additive block names one future frozen member and one owner entry only:
`scripts/product-truth/sqlite-classifier.ts#classifyRetiredSqliteBundle`. It also names the exact
`retiredBundle`, `invocationScratchRoot`, `classifierCopyPath` and `classifierDatabase` flow plus the
four resolver/create/copy/open/remove declarations. The meter must resolve every declaration and
local exactly once in that path and derive the actual caller, parameter, path, handle and completion
flow. A similarly named function, another file, config claim or meter-authored path list cannot
establish the origin.

### Retired source cannot become current-state authority

`retiredBundle` must derive exclusively from `resolveRetiredSqliteBundleTarget`, the canonical
default OmniMind root, exactly one `dev` or `userdata` lane, an exact retired main basename
`product-state-v1.sqlite` or `state.sqlite`, its exact optional `-wal`/`-shm` siblings and the
`exact-retired-tool-target` disposition. Outside-root/lane, merged, unknown and current
`stores/product.sqlite` / `stores/service.sqlite` sources fail. Thus the two old basenames are not a
textual allowlist for arbitrary SQLite access and cannot discharge current state.

### Private scratch is bounded rather than a temp exemption

The only scratch root is the exact `invocationScratchRoot` created by
`createClassifierScratchRoot`. It must be newly and exclusively owned by that classifier invocation,
mode `0700`, outside the retired source and canonical current-store ancestors; the exact copy is a
strict descendant created exclusively with mode `0600`. The accepted Direct Rebuild Design further
binds this to a receipt-random private OS-temp directory. A raw `os.tmpdir()` result, environment or
caller path, another temporary root, a path merged with a non-authorized origin, or a source/current
ancestor is explicitly invalid. The fact that the private directory is physically below the OS temp
root therefore does not authorize the OS temp root or any sibling: only the fresh exact child and its
strict descendant copy participate.

### Copy and SQLite handle remain proof-bound

The source is opened no-follow/read-only and the destination exclusive-create. Source identity
before/after, copy identity before SQLite open, `nlink=1`/no-follow, byte count, SHA-256 and the
repeated complete source-bundle manifest are conjunctive. Only `classifierCopyPath` may reach
`openClassifierCopyReadOnly`, and only a resolved read-only/no-create open may create
`classifierDatabase`; the source handle, current-path copy, raw current alias and merged path are
closed failures. This gives the private copy the exact path provenance absent from the failed design
without weakening the inherited v4 primitive/opener/receiver fixed point.

### Cleanup closes every valid disposition

After scratch acquisition, every reachable normal, return, throw, catch and finally completion is
analyzed. A valid completion must close the database when acquired, link-safely call the exact
`removeClassifierScratch` finalizer and prove the exact scratch root absent before a safe return or
later operation. Conditional, detached, bypassed or missing removal; a catch/finally path that skips
absence; retained evidence; or a cleanup failure claimed as safe all fail
`DIRECT_TOOL_CLASSIFIER_COPY_ORIGIN_INVALID`. Failure may stop the tool, but it cannot be relabeled as
a valid classified disposition or authorize `apply`.
