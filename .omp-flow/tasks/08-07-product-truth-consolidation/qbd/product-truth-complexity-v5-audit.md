## Verdict

**FAIL**

- Decision-critical blocking findings: **1**
- Advisory observations: **0**
- Total findings: **1**

V5 correctly repairs the five observed v4 bypass classes in its control-flow and lock contracts.
The specified forward must-analysis assigns a fresh acquisition identity per event/context, meets
actual predecessors, makes detached release-capable scheduling unknown, and treats unsupported
proof-relevant JavaScript/Effect flow as a closed failure. Its bounded CFG/ICFG covers the required
present/absent polarity, zero-iteration `for`/`for...of`/`while`, one-or-more `do`, abrupt completion
and catch/finally continuations. Those rules are conservative and implementable; they do not claim
to decide arbitrary JavaScript. The five failed-v4 witnesses and inherited matrix are conjunctive,
the five production fences remain byte-identical, and the downstream acceptance order remains
closed.

One authority contradiction still blocks implementation. The new direct-tool-inclusive capability
domain must analyze the B1 SQLite classifier, but v5 also freezes the v4 approved path-origin block
without addition. That block has no exact origin for the direct rebuild tool's private classifier
copy. Consequently a conforming meter must either reject the required B1 classifier as unknown or
invent an unpinned direct-tool non-Product discharge. The first makes the core B1 path unrealizable;
the second restores self-authored provenance authority at the irreversible admission gate.

## Blocking finding

### B1 — the closed SQLite path-origin authority has no direct-tool classifier-copy origin

**Cause.** V5 inherits the v4 capability interface unchanged unless it explicitly strengthens it,
and expressly requires the exact `omp-flow-database-capability-authority-v1` block to remain
unchanged, rejecting any additional authority. That block closes `proved non-Product` to six exact
origins: canonical Product, canonical Service, one Service-owned classifier scratch local and three
declaration-scoped `:memory:` origins. It says every persistent component left outside those exact
origins is unknown and hard-fails; absence of Product-looking text, file/callee names or a
meter-authored list cannot discharge it
([v4 interface](../interfaces/product-truth-complexity-v4.md), lines 44-65 and 105-124;
[v5 interface](../interfaces/product-truth-complexity-v5.md), lines 16-28).

V5 then expands candidate capability discovery to every `production` and `direct-tool` member. The
required B1 tool must create a private copy of each retired main/WAL/SHM bundle, open only that copy
with SQLite, run integrity/foreign-key/DDL/metadata and protected-fact aggregate SQL, and remove the
scratch tree before success ([Design](../design.md), lines 246-298;
[B1 Work](../work/direct-first-public-b1.md), lines 49-56). The frozen B1 fence names
`scripts/product-truth/sqlite-classifier.ts`, but the strict capability block contains no declaration
or local in that path and no `ephemeral-direct-tool-classifier-copy` class. The v5 sentence that
direct-tool current/retired identities remain classified by the “exact tool authority” does not add
a path/config origin, copy-provenance rule or strict machine input; inherited tool-only literal
classification names retired target identities, not the generated scratch path passed to
`Database`/`DatabaseSync`. The mandatory positive merely demands that an operation be explicitly
classified; it does not supply the missing independent authority.

**Concrete consequence.** A faithful implementation has only two outcomes. If it applies the closed
v4 origin rule, the required SQLite open of the tool-owned private copy is an unknown persistent
component and every repaired B1 candidate fails before it can satisfy the accepted database
classifier/protected-preflight contract. If it adds a config-only or implementation-only
“direct-tool scratch” exemption, the meter—not the accepted Design—chooses what copied path is safe.
That exemption can authorize an unintended persistent path or raw current-state alias while the
report claims complete Product provenance. Either outcome defeats R2/R11 and A2/A9/A14: the first
makes the indivisible B1 core path unrealizable, while the second can falsely admit an irreversible
candidate through self-authored provenance authority.

**Affected decision.** The [PRD](../prd.md) requires WAL-aware private-copy classification before
any deletion and makes v5 the sole gate for every database consumer. The [Design](../design.md)
requires both that classifier and an independently rooted complete capability graph. The
[v5 meter Work](../work/product-truth-complexity-v5.md) may not change Product/direct-tool behavior
or add authority outside its allowed instrument paths. A v5 implementation cannot satisfy all three
simultaneously under the current checkpoint.

**Smallest remedy.** Add one strict v5-owned additive authority input, or supersede the v1
capability block with an exact v2 block, that names the future direct-tool classifier declaration and
local/config origin used for the private copy. Give it a distinct class such as
`ephemeral-direct-tool-classifier-copy` and require: derivation from an exact retired tool target,
containment under the invocation-owned freshly created private scratch directory, no-follow/copy
identity binding, read-only SQLite open, and cleanup on every finally/abrupt exit. Re-extract and pin
that block independently. State explicitly that this class cannot classify current
`stores/product.sqlite`/`stores/service.sqlite`, a source database opened in place, an unbound temp
path or any raw current Product alias. Add a positive private-copy classifier flow and negatives for
current-path copy/open, source-in-place open, unbound temp copy and missing-finally cleanup; retain
the failed-v4 direct-tool raw Product SQLite/DELETE negative.

**Why hiding, unavailable, narrowing or safe degradation is insufficient.** Treating the direct
tool as unknown and unavailable is fail-closed but removes the only authorized mechanism that can
prove the retired database identity and protected-fact absence before deletion; B1 cannot realize
its accepted outcome. Excluding direct-tool from capability analysis recreates the exact v4 P0.
Avoiding SQLite or delegating to an unmodeled external program replaces the required exact
classifier with a new unresolved persistence authority. The missing path origin must therefore be
closed in Design before meter implementation.
