repair. It is not complete with Design or Markdown planning alone. The delivery includes:

1. singular durable document authority and one read route;

3. exact-source/identity governance derived from declared immutable adoption metadata, including
   exact-zone/tool-root ancestry disjointness and zone-external leakage checks;
4. a bounded document-contract validator;
5. focused negative/positive tests, source and identity checks, and one green frozen-candidate
   quality gate;
6. a formal commit containing only the accepted delivery and its durable Bundle knowledge.

## Explicit non-completion boundary

Completing this Bundle does not complete OmniMind, M2 or the overall Campaign. The next
implementation task must be explicit and product-facing:

- UI mother source-domain map and real UI takeover;
- isolated Pi Native Host;
- Product/Engine state and authority boundaries;
- deletion of the old incorrect Runtime/state concepts as their real replacements land.

The documentation/governance result is a construction boundary for that work, not a substitute
for it and not evidence that the product UI or Runtime has been implemented.

## Priority rule

Real product progress outranks procedural perfection. omp-flow protects bounded construction,
independent review and durable knowledge; it must not become an infinite audit loop or a Markdown
production system. Further audit is justified only by a new material finding, failed proof or
materially changed scope.
