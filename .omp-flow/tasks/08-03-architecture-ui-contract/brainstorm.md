# Brainstorm: Preserve OmniMind architecture and UI contract

The observable problem was not a shortage of prose. A previous doctrine reset compressed several information lifetimes into root files and silently removed detailed UI contracts. A fresh Agent could therefore read a concise, internally plausible README and still delete approved workbench behavior or inherit the wrong execution authority.

The principal contradiction is: OmniMind must preserve a complete mature product chassis and UI lineage, while preventing that chassis from becoming a second native Agent Harness. Solving only the first half creates duplicate execution authority; solving only the second half triggers a costly product rewrite and loses hidden UI behavior.

The irreducible outcome is a single navigable truth system:

- [`README.md`](../../../README.md) states product identity and non-negotiable doctrine;
- [`architecture/`](../../../architecture/README.md) contains accepted stable contracts;
- [`research/`](../../../research/README.md) contains falsifiable evidence and superseded decisions;
- [`execution-brief.md`](../../../execution-brief.md) contains order only;
- the active Campaign contains status only.

Human-confirmed boundaries:

- the complete fixed UI source is the physical mother, not a screenshot reference;
- `Agent | Chat` and Projects above Groups remain fixed;
- Settings uses `Models / Agents / Packages`;
- current work may classify and repair documentation, but must not opportunistically implement Runtime, state, Package or topology changes;
- naming must be short, stable, domain-based and free of research or donor identities;
- detail is required so a fresh Agent does not depend on this conversation.

The strongest counter-hypothesis is that one giant root README would be safer because every rule is visible in one place. Repository history falsifies that approach: the file became thousands of lines, mixed evidence with authority, and later compression deleted material UI contracts. The safer design is not less information; it is explicit information ownership plus task routing.

Evidence that would revise this framing:

- a material requirement cannot be assigned to exactly one document authority;
- the split causes contradictory wording that cannot be resolved by links and precedence;
- the UI contract still requires prior chat to interpret a normal, failure or recovery path;
- the source review cannot distinguish fixed-source fact from product decision;
- a fresh independent reviewer identifies a material missing or competing authority.

No consequential human question remains. The user confirmed the only material IA fork, `Models / Agents / Packages`, and authorized execution.
