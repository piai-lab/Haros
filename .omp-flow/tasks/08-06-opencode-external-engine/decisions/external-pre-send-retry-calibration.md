# Contain external pre-send unavailability

Main selected a readable Product boundary for a lost external prepared handle before send. Startup
keeps the existing Run/dispatch pending at attempt zero and records only bounded, retryable
selected-Engine unavailability. It never prepares or sends that prompt automatically. Only the
typed exact-dispatch Retry command, or the exact duplicate submit identity as its idempotent
transport, may reprepare the frozen Engine/selection/lineage and cross `markSent` once.

The affected Conversation remains single-owner while Product, Pi and other Conversations remain
available. No fallback, background replay, generic retry or new durable authority is created.
Malformed or contradictory durable state and non-retryable preparation rejection remain
fail-closed. Pi's default pre-send, accepted-operation and recovery semantics remain unchanged.
