# Deliver one OpenCode external-Engine vertical slice

## Authorized execution view

This Bundle has one implementation Work:

- [Deliver a truthful OpenCode next Run](deliver-truthful-opencode-next-run.md) implements the
  atomic Product protocol/store migration, literal Pi/OpenCode execution gateway, concrete
  OpenCode ACP process boundary, next-Run Workbench choice and the focused real/fault proof as one
  reviewable vertical slice.

One Work preserves the contract's single candidate handoff and exactly one different-actor review.
Contracts, Service and Web are not independent product outcomes here: each changes the same closed
selection/receipt/catalog protocol and none is shippable without the other two.

Implementation still follows useful internal order. First freeze the v2 closed contracts, the
startup-only crash-recoverable Product+Automation two-store coordinator and the separate recoverable
Web draft migration.
Next land the source-neutral Product gateway/Native Host mapping.
Only then can the concrete OpenCode boundary and Web choice proceed on non-overlapping paths; the
canonical Executor integrates them and runs deterministic faults. The two real candidate journeys
run only after the full tree is frozen. These are coordination waves inside one Work, not a second
task graph or generic Engine program.

## Completion boundary

The Work completes only with one linked handoff covering normal, unavailable, pre-observation,
post-observation, cancel/late-final, restart/no-replay and exact migration behavior plus one real
OpenCode and one smallest changed-seam Pi journey. A different actor then reviews the complete
candidate once. No producer may mark F-13 verified, start F-12/F-14, add Remote/release work or
interpret partial green checks as acceptance.
